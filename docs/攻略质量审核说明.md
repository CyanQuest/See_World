# 攻略质量审核与修改闭环

流程为资料整理、地点目录、路线草案、路线检查、正文、审核、问题分类、针对性修改。仅使用已配置的攻略模型；B站仍是唯一的视频搜索来源。

门槛保持至少85分且无关键错误。五维权重为35、20、20、15、10，每维五档，程序校验整数范围并计算总分与档位。预算完整性不计分；明确预算上限、已写价格及计算正确性继续检查。

审核不通过后，GLM使用正文、审核意见和原文证据区分可修复问题与真正证据缺口。默认每批最多修改两轮，可以在设置保存0—2轮。每轮产生新版本，记录上版、实际变化的章节、待修问题和剩余证据需求。复审无分数改善或达到轮数上限就停止本批文字修改。没有明确证据需求时不补视频；确有缺口才使用具体路段、地点、月份生成B站搜索词。每批最多5个、累计最多15个，失败尝试计数，同一视频重试不重复计数。达到上限不降分数门槛。

地点目录保留名称、别名、城市/片区、类别、事实编号及冲突。编号可追溯到原视频。同名不自动合并，含冲突的地点保守降为未确认，禁止进入核心路线。路线草案包含起终点、活动顺序及建议停留、路段依据与缺项、用餐休息入住、机动和当天删减预案。GLM独立检查草案，明确不成立的方案在写作前最多调整两次；仍无法通过则暂停并保留草案。

审核意见属于修改建议，不是事实来源。正文中的事实必须引用本轮发送的原文编号。未知编号直接拒绝，不再替换成占位句。JSON不执行任何表达式；仅接受合法JSON、标准围栏去除和文末缺少闭合大括号的确定性恢复。字段类型严格校验；结构错误最多发起一次有错误说明的纠正请求，原始响应仍保存在请求缓存。标为planning的段落统一带建议标签，仍须接受事实与数值审核。

正文先清理主题章节中的固定占位句和逐字重复段落，再保存并审核。审核同时接收最终Markdown正文，保存SHA-256便于核对。页面、复制、导出和打印使用相同正文；审核附录独立展示。最终正文不包含资料冲突章节，来源仅保留标题、链接、发布日期和作者；事实卡片、转写全文与内部冲突不删除。

任务页统一显示视频、音频、请求数、任务tokens的已用/上限/剩余，以及最近请求的上下文与输出用量。任务tokens包含未知请求的保守预留，上下文采用UTF-8输入字节加输出预留的保守估算，不等同于服务商精确tokenizer。每个阶段可使用低于设置上限的输出预算，最近请求显示实际采用值。保存设置后在暂停任务点击继续，更新任务限制快照，已保存的阶段和正文保持复用。

持久化表：quality_cycles保存主阶段、版本、批次、文字轮次、上轮分数、分类与历史；editorial_steps保存写作资料、地点目录、路线、检查及完成的正文；request_metrics保存最近一次请求预算。已保存正文的审核重试不重新写作，纯文字修改不调用下载或转写。结果未知请求仍要求用户核对服务商记录，不能自动重发。

数据库使用增量建表与增列，旧任务、设置和历史版本不重建。整改前SQLite在线备份位于data/backups/before-editorial-20260911.sqlite3；密钥仍使用原来的.secrets目录。恢复数据库时应先停止应用并保留当前数据库副本。

真实验收记录另见整改验收记录。模型评分与路线判断仍是模型判断，不能替代实时地图、官方开放或预约信息核验，软件不会虚构这些资料凑85分。
