# 见世界 · 旅行攻略生成器

个人使用的中文本机 Web 应用。输入目的地，搜索 Bilibili 旅行视频，优先提取字幕；需要时下载音频并调用 `moss-transcribe-1.0`，再通过你配置的攻略模型整理有来源依据的行程。

**当前交付：可运行的本机应用，已完成一次真实目的地到攻略全流程。** 成都任务从 19 条候选中确认 5 个视频，完成 Moss 转写、GLM 整理、原文抽查与 Markdown 导出；当前 129 项本地和模拟测试通过。真实示例以美食为主，仍有转写歧义和资料缺口，不能视为已通过全部 V1.0 真实验收。详见 [验收记录](docs/验收记录.md)、[真实联调记录](docs/真实联调记录.md) 和 [真实生成示例](docs/成都_真实生成示例.md)。

## 打开应用

当前开发机器已安装依赖并完成构建。

1. 双击项目目录中的 `start.command`。
2. 浏览器打开 <http://127.0.0.1:8765>。
3. 进入「连接与设置」，分别填写两组 API。填写完点击「保存设置」。
4. 新建攻略，输入目的地。默认 3 天、1 人、适中节奏，可展开更多偏好。
5. 搜索受限时，在任务页补充标准 Bilibili 视频链接，或先在设置页导入 Cookie 后重试。

在启动终端按 `Ctrl+C` 停止服务。已完成的文本与攻略不会丢失。再次启动自动恢复可安全继续的阶段；已提交但结果不确定的请求会暂停，需要用户明确确认后才会重试。

## 在其他机器安装

支持 Python 3.11+、Node.js 20.19+ 或 22.12+。已在 macOS / Apple Silicon / Python 3.12 验证。当前启动脚本和 worker 文件锁针对 macOS/Linux；Windows 不在已验证范围。

```sh
./install.command
./start.command
```

如果系统默认 Python 版本较旧：

```sh
TRAVEL_PYTHON=/你的/python3.12/路径 ./install.command
```

安装脚本使用 `requirements.lock` 和 `frontend/package-lock.json` 锁定依赖。首次安装需连接 PyPI 和 npm。音频处理优先使用系统 FFmpeg；没有时使用锁定的 `imageio-ffmpeg` 二进制。ffprobe 可选，缺少时通过 FFmpeg 检查时长和音轨。

开发运行：

```sh
# 终端一：后端，默认只允许本机
.venv/bin/python -m uvicorn backend.app:app --host 127.0.0.1 --port 8765
# 终端二：后台任务
.venv/bin/python -m backend.worker
# 终端三：前端热更新
cd frontend
npm run dev
```

开发前端为 <http://127.0.0.1:5173>，通过代理调用本机后端。请勿同时运行两套后端/worker；操作系统文件锁会阻止重复 worker。

## 配置 API

### Moss

- 默认 Base URL：`https://api.mosi.cn`
- 接口：`POST /v1/audio/transcriptions`
- 固定模型：`moss-transcribe-1.0`
- Bearer 鉴权、multipart 文件上传，读取 JSON `text`。
- 不向转写接口传 Bilibili 网页链接，不使用热词参数，不伪造句子级时间戳。

### 攻略模型

填写服务商名称、HTTPS Base URL、模型名和 API Key。第一版实现 **Chat Completions** 协议，即 `POST /v1/chat/completions`。Base URL 可以带末尾 `/v1`；智谱可填写 `https://open.bigmodel.cn/api/paas/v4`，程序保留服务商的路径前缀，不重复添加 `/v1`。

智谱 GLM-4.5～4.7 使用 `thinking.type=disabled`；GLM-5.3 实际接口要求始终思考，使用其支持的 `reasoning_effort=low`，为 JSON 最终回答保留输出预算。不会更换用户选定的模型。

其他协议需要在 `backend/providers.py` 增加适配器，不能仅改地址便假定兼容。模型必须能按提示返回 JSON 对象；结构或引用不合格时提示错误并最多请求纠正一次，不猜测未知引用。

连接测试会产生真实请求，可能收费。Moss 测试上传 1 秒静音，仅证明该请求返回了合约字段；它不能证明真实语音识别质量。攻略模型测试请求最多输出 512 tokens（包含需要时的模型思考开销）。

也可在启动前通过环境变量设置 `MOSS_API_KEY`、`LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`；环境变量优先于设置页保存值。**不要在源码或公开对话里放密钥。** `.env.example` 仅作变量示例，应用不会自动读取 `.env`。

## 视频、字幕与引用

### GLM 正文写作提示词

最终攻略由 GLM 撰写连贯正文，固定提示词在 [prompts/glm_travel_writer.md](prompts/glm_travel_writer.md)。每次生成读取完整文件，配合出行需求、来源日期与链接、按四类均衡选取的事实及原文句子发送。为控制上下文长度，原文按相关句子节选；未发送数量显式传给模型，完整转写始终保留。

模型输出概览、逐日正文和六个主题章节；程序验证引用编号、数字依据和四类覆盖，统一排版。实际提示词、输入资料和模型正文随攻略版本保存。输入示例见 [GLM写作输入示例](docs/GLM写作输入示例.json)。编辑提示词文件后，下次生成即采用新内容；不需要重新转写视频。

- 住、行、玩、吃四组基础搜索词，每组默认 10 条；兴趣最多增加两组；BV/AV 解析后按 BVID 和分 P 去重。
- B 站搜索使用带 WBI 签名的站内视频搜索接口；查询成功结果按登录配置隔离缓存 6 小时，搜索请求至少间隔 2 秒，失败后冷却 5 分钟。Cookie 修改后不复用旧登录配置的搜索缓存。
- 自动筛选优先补齐四类标题主题，缺类时暂停等待补充或手动确认；标题匹配不等于内容验证。
- 默认最多 5 个视频、总共 60 分钟、单条 30 分钟。人工选择也校验这些上限。
- 仅接受标准 `https://www.bilibili.com/video/BV…` / `av…` 链接。分 P 用 `?p=2` 保留，不自动下载合集。
- 不将弹幕、简介或评论作为语音字幕。中文字幕必须满足格式、时间顺序、有效文字数和覆盖率检查，默认至少 100 字、覆盖至少 50%。
- 音频默认约 5 分钟一段，重叠 2 秒，优先使用附近静音点。FFmpeg 检查完整音轨、实际时长、解码和分片体积。
- 原文完整保留；导出来源节选折叠异常重复、限制长度并去重，完整文本在来源详情中查看。带疑点事实保留于待核实项，不列入推荐章节。
- 事实卡片保存原文摘录、来源和时间范围。程序校验摘录存在、引用编号和数值引用，不等于自动证明语义绝对正确。
- 原文保留；预算不把口径不明、币种不同或同一项目的不同报价相加。缺少人数/次数等依据时总预算标记未知。
- 模型先整理地点目录、生成并检查路线草案，再写正文；程序保留证据、结构校验与 Markdown。地图、天气、当前价格均未接入。

## 资料修改闭环（2026-09整改）

任务页「利用现有资料修改」可从当前未达标版本继续，先重排路线与正文，再复审；每批默认最多两轮，轮数可在设置保存。只有明确证据缺口才触发B站定向补充搜索，每批最多5个、累计最多15个。达到上限仍不合格会保留未达标状态。

正文、审核输入与复制/导出/打印统一；评分附录独立展示。任务页显示资源余量、当前阻塞、恢复阶段与每轮修改记录。暂停后保存新设置，再点击继续应用限制；已完成的资料、路线和正文不重复付费生成。详细规则见[攻略质量审核说明](docs/攻略质量审核说明.md)。

## 任务、重试和导出

- 后台 SQLite 队列；一个完整任务同时运行，转写默认并发 2。
- 每 3 秒更新 worker 心跳。刷新/关闭浏览器不会中止任务。
- 认证错误停止反复尝试；限流最多重试两次并遵循 `Retry-After`。付费请求提交后超时或服务端结果不确定时记为未知，默认不自动重发。
- 已成功转写的分片不重复提交；同一任务的相同服务请求持久化缓存。修改偏好复用来源文本并生成新版本。
- 缓存当前隔离在各任务内。新建独立任务处理相同视频仍可能重新下载或转写，不声称跨任务免费复用。
- 来源较少、过旧、部分失败时保留警告。完全无有效事实时不生成普通攻略。
- 攻略支持复制、Markdown 下载和浏览器打印 PDF；来源原文支持 TXT 导出。

## 数据、凭据与备份

```text
data/travel.sqlite3       任务、来源、文本、事实、分片、版本、事件、使用量与响应缓存
data/media/<任务>/<来源>/ 下载媒体与音频分片
data/worker.lock          单 worker 文件锁
.secrets/master.key       Fernet 加密主密钥（与业务数据库分开存储，权限 0600）
```

API Key 和 Cookie 加密后存入设置表。浏览器不能重新读取明文密钥，也不把密钥写入 localStorage。主密钥可以用 `TRAVEL_SECRET_DIR` 指定到另一个受保护目录；`TRAVEL_DATA_DIR` 可指定数据目录。

备份前停止应用，复制 `data/` 与 `.secrets/`；恢复时两者必须配套。只备份数据库无法解密保存的凭据。这一方案保护静态存储，不抵御已经控制本机账号的恶意程序。

Cookie 导入只保留 Bilibili 域。临时 Cookie 文件权限 0600，用完删除。所有输入不经 shell 拼接执行；视频与媒体地址限制为允许域名的公网 HTTPS；写接口校验本机 Host、Origin 和会话标识。仅适用于本机使用，勿直接暴露到公网。

默认成功任务的媒体 24 小时后清理，其他停止任务 7 天后清理；「保留媒体」开启则保留。清理不会删除字幕/转写文本或攻略。删除任务会清理其所有本地关联记录和媒体，不代表删除第三方服务保存的数据。

## 测试、更新与排错

```sh
.venv/bin/python -m pytest -q
cd frontend && npm run build
```

只读真实搜索诊断（不下载视频、不调用付费 API）：

```sh
.venv/bin/python scripts/check_bilibili.py
```

- **Bilibili 412 / 403 / 登录限制**：导入有访问权限的 Bilibili Cookie，或稍后重试；也可粘贴标准视频链接。不会自动绕过验证码、会员或访问限制。
- **API 401 / 403**：检查地址、密钥、模型权限和账户状态。
- **请求结果未知**：先查看服务商记录，再决定是否确认重试；应用级幂等不能保证服务商绝不重复计费。
- **模型结构不合格**：已有事实与原文保留，尝试兼容 JSON 输出的模型或调整上下文预算。
- **上限不足**：在设置调整资源限制后继续任务，新限制在重试时更新快照。
- **端口占用**：关闭之前运行的应用实例再启动。
- **FFmpeg 不可用**：重新运行安装脚本，或在系统安装 FFmpeg。

升级 yt-dlp 时显式修改依赖版本，重新锁定和测试；应用运行时不会自动更新。数据库当前为 schema version 3，初始化增量建表、增列，保留历史记录；破坏性模式变更须先备份。

## 代码结构

- `backend/app.py`：HTTP API、本机保护、历史、设置、导出。
- `backend/store.py`：SQLite 与加密配置。
- `backend/worker.py`：持久化任务、心跳、取消、转写并发与清理。
- `backend/media.py`：搜索/下载、字幕解析、FFmpeg 分段与合并。
- `backend/ytdlp_guard.py`：yt-dlp 的请求/重定向域名和公网地址校验。
- `backend/providers.py`：Moss/攻略模型协议、重试、使用量与请求缓存。
- `backend/guide.py`：分段事实、来源检查、行程编排与导出内容。
- `frontend/src/`：React + TypeScript 中文界面。

需求参考：用户提供的《旅行攻略生成软件_需求文档_V1.0.md》。第三方接口依据 [Moss 官方转写文档](https://platform.mosi.cn/docs/reference/transcriptions/) 与 [yt-dlp 官方 Bilibili 提取器](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/bilibili.py)。
